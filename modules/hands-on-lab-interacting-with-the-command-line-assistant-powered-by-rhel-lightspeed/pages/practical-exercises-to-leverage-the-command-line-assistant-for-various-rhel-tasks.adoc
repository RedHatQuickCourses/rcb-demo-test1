#  Practical exercises to leverage the command-line assistant for various RHEL tasks

[#_practical_exercises_rhel_lightspeed]
= Hands-on Lab: Interacting with the Command-Line Assistant Powered by RHEL Lightspeed

This lab is designed to provide you with practical, hands-on experience in leveraging the AI-driven expertise of the Red Hat Enterprise Linux (RHEL) Lightspeed command-line assistant. You will explore its capabilities for common RHEL tasks, including system configuration, management, and troubleshooting. By the end of this lab, you will be proficient in using this powerful tool to streamline your RHEL administration workflows.

== Prerequisites

Before you begin this lab, ensure you have:

*   Access to a RHEL system (physical or virtual machine) with the RHEL Lightspeed command-line assistant installed and configured.
*   Basic command-line familiarity with RHEL operations.
*   `sudo` privileges on the RHEL system for executing administrative commands.

== Exercise 1: Seeking Configuration Assistance

The RHEL Lightspeed assistant can significantly simplify system configuration by providing instant, accurate commands and guidance. This exercise will demonstrate how to use Lightspeed for common configuration tasks.

=== Task 1.1: Installing Software Packages

Learn how to ask RHEL Lightspeed for the correct `dnf` command to install a package and then execute the suggested command. This illustrates how Lightspeed acts as an intelligent guide, ensuring you use the most efficient and accurate commands.

.  **Open your terminal.**
.  **Ask RHEL Lightspeed how to install a package.** For this task, let's use `htop`, a popular interactive process viewer.
+
[source,bash]
----
lightspeed How do I install the htop package?
----
.  **Analyze Lightspeed's response.** The assistant should provide a clear command, likely using `dnf`.
+
[NOTE]
The output from Lightspeed might include additional context or explanations before the suggested command. Focus on the command itself.
.  **Execute the recommended command.** This will install `htop` on your system.
+
[source,bash]
----
sudo dnf install htop -y
----
.  **Verify the installation.** Run `htop` to confirm it's installed and functioning.
+
[source,bash]
----
htop
----
.  **Exit `htop`.** Press `q`.

=== Task 1.2: Configuring Firewall Rules

Firewall configuration can sometimes be intricate. Use RHEL Lightspeed to quickly get the commands needed to open a specific port using `firewalld`.

.  **Query Lightspeed for firewall configuration.** Ask how to open a common service port, like HTTP (port 80) permanently.
+
[source,bash]
----
lightspeed How do I open port 80/tcp permanently using firewalld?
----
.  **Review the suggested `firewall-cmd` commands.** Lightspeed will provide the necessary commands to add the rule and reload the firewall.
.  **Execute the commands provided by Lightspeed.**
+
[source,bash]
----
sudo firewall-cmd --add-port=80/tcp --permanent
sudo firewall-cmd --reload
----
.  **Verify the new firewall rule.**
+
[source,bash]
----
sudo firewall-cmd --list-all
----
.  **_Optional:_ Remove the rule after verification.** It's good practice to clean up lab changes. Ask Lightspeed how to remove it, or use the inverse command.
+
[source,bash]
----
lightspeed How do I remove port 80/tcp permanently using firewalld?
sudo firewall-cmd --remove-port=80/tcp --permanent
sudo firewall-cmd --reload
----

== Exercise 2: Troubleshooting with AI-Driven Expertise

One of the most powerful features of RHEL Lightspeed is its ability to assist with troubleshooting. By analyzing context or explicit questions, it can guide you toward solutions for common system issues.

=== Task 2.1: Diagnosing a Service Failure

In this task, you will simulate a `sshd` service stop and then use Lightspeed to help diagnose and restart it, demonstrating how the assistant aids in service management and troubleshooting. This directly leverages the capability mentioned in the context for "troubleshoot SSHD service failing to start."

.  **Stop the `sshd` service.** This will simulate a service failure scenario.
+
[source,bash]
----
sudo systemctl stop sshd
----
.  **Check the status of the `sshd` service.** Observe that it is `inactive (dead)`.
+
[source,bash]
----
systemctl status sshd
----
.  **Ask RHEL Lightspeed for troubleshooting assistance.** Provide context about the service that is not running.
+
[source,bash]
----
lightspeed My sshd service is not running. How can I troubleshoot it?
----
.  **Analyze Lightspeed's suggestions.** The assistant should provide steps to check logs (e.g., `journalctl -u sshd`), examine configuration, and attempt to start/enable the service.
.  **Use Lightspeed to get the correct commands to start and enable `sshd`.**
+
[source,bash]
----
lightspeed How do I start and enable the sshd service?
----
.  **Execute the recommended commands** to bring the `sshd` service back online and ensure it starts on boot.
+
[source,bash]
----
sudo systemctl start sshd
sudo systemctl enable sshd
----
.  **Verify the `sshd` service is now running and enabled.**
+
[source,bash]
----
systemctl status sshd
----

== Exercise 3: Advanced Interaction and History Review

RHEL Lightspeed can integrate with your current terminal session by processing command output or by allowing you to review your past interactions, enhancing its utility for more complex scenarios.

=== Task 3.1: Analyzing Command Output with Lightspeed

Learn how to pipe the output of a standard RHEL command directly into Lightspeed for analysis and suggestions. This is particularly useful for large log files or complex command outputs where manual parsing might be time-consuming.

.  **Generate some system log output.** For this exercise, we'll get recent entries from the system journal.
+
[source,bash]
----
journalctl -xe --since "10 minutes ago"
----
.  **Redirect this output to RHEL Lightspeed for analysis.** Ask Lightspeed to interpret or provide insights based on the logs.
+
[source,bash]
----
journalctl -xe --since "10 minutes ago" | lightspeed analyze this output for errors or warnings
----
.  **Review Lightspeed's analysis.** The assistant will summarize the output and may suggest troubleshooting steps if it identifies any critical events.
+
[NOTE]
The relevance of Lightspeed's analysis will depend on the actual content of your logs. If there are no significant errors or warnings, Lightspeed might simply state that.

=== Task 3.2: Reviewing Interaction History

The `lightspeed` assistant keeps a history of your interactions. This feature allows you to quickly recall previous questions and the solutions or advice provided, which is invaluable for recurring tasks or forgotten commands.

.  **Ask RHEL Lightspeed to display your interaction history.**
+
[source,bash]
----
lightspeed history
----
.  **Scroll through your interaction history.** Observe how past queries and Lightspeed's responses are displayed, offering a useful record of your troubleshooting and configuration journey.
